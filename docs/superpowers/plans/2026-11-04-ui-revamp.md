# UI revamp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A TV-first remote: an All TVs view of cards, a One TV remote, and a `/share` picker so a link shared from the iPhone plays on the TV you tap, with a quiet buffering indicator.

**Architecture:** The server keeps a cached "card" per TV, refreshed in the background with a per-TV deadline, and serves it from `/api/targets` without ever waiting on a TV. The front end stays one dependency-free `app/index.html` with a hash router (`#/`, `#/tv/<id>`, `#/share`). `/share` serves the same file; the picker POSTs the existing `/api/play?target=`.

**Tech Stack:** Python 3 / Flask / waitress (existing), `unittest` for backend tests (stdlib, no new dependency), vanilla JS/CSS, Chrome plus a local stub server for front-end checks.

**Spec:** `docs/superpowers/specs/2026-11-04-ui-revamp-design.md`

## Global Constraints

- Existing API stays: `/play`, `/api/play`, `/api/cmd`, `/api/status`, `/api/targets`, `/api/roku`, `/api/tv`, `/api/debug`, and the `?target=` parameter.
- TVs are `living` (Pi on HDMI, mpv) and `bedroom` (Chromecast); targets stay hard-coded server-side.
- One dependency-free HTML file for the UI; no frameworks, build step or libraries.
- Phone-first at 390 px, large touch targets (44 px minimum), dark, Canadian spelling, works as an iOS Home Screen web app.
- Password support stays: Basic auth for the UI, `&t=` only for `/play`; `/share` and the API calls from it rely on the browser's credentials.
- No real addresses or device names in the repo; test data uses placeholders.
- Per-TV deadline for card data is 2 s; the picker is interactive in under 1 s.
- Never fall back to another TV when the chosen one fails.
- Do not touch the Pi or the Chromecast while Ben is running a soak test; front-end checks use the local stub server.

## Review Focus

1. One TV is slow or unreachable while the other is fine: the picker is usable at once, the slow card says "Can't reach", and tapping the good card still plays.
2. The shared text has no usable link, or extra words around it: the picker says no link was found and offers a paste box; it never plays anything.
3. A TV is still starting when its card renders: the card says "Starting…", not "Idle".
4. The chosen Chromecast is offline: the play fails with a readable message on that card and nothing starts on the living room.
5. Very long titles, emoji and a 390 px width: no horizontal scroll, text wraps or truncates, targets stay 44 px.

### Task 2: Card cache and health

**Files:**
- Create: `app/targets.py`
- Test: `tests/test_targets.py`

**Interfaces:**
- Produces:
  - `health(kind: str, status: dict) -> {"state": "smooth"|"buffering"|"starting"|"idle"|"error", "drops": int|None, "start_s": float|None}` where `kind` is `"pi"` or `"chromecast"` and `status` is the target's `/api/status` dict. Rules: `error` when `status.get("error")`; `starting` when `status.get("starting")`; `buffering` when `status.get("buffering")`; `smooth` when `status.get("running")`; else `idle`.
  - `class Cards(providers: dict[str, Callable[[], dict]], order: list[str], timeout: float = 2.0, every: float = 3.0)` with `start() -> None` (background refresher thread), `refresh_now() -> None`, `snapshot() -> list[dict]` (cards in `order`, never blocks). Every card gets `"id"` and `"reachable": bool`; an unreachable card keeps its last good fields and `reachable=False`.

- [ ] **Step 1:** Tests in `tests/test_targets.py`: `test_health_rules` (one assert per rule, including that `error` beats `buffering`); `test_snapshot_does_not_wait_for_slow_provider` (provider sleeping 5 s, `timeout=0.2`; `refresh_now()` then `snapshot()` returns in under 0.5 s with that card `reachable=False` and the other card complete); `test_unreachable_keeps_last_good_fields` (provider succeeds once, then raises; second snapshot keeps `name`, `reachable` is False).
- [ ] **Step 2:** Run `python -m unittest tests.test_targets -v`; expect FAIL (module missing).
- [ ] **Step 3:** Implement `app/targets.py`. Run each provider in its own thread per refresh with `join(timeout)`; a provider still running at the deadline counts as unreachable and its late result is discarded.
- [ ] **Step 4:** Run the tests; expect PASS.
- [ ] **Step 5:** Commit `feat: cached TV cards with per-TV deadline and health`.
